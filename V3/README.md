# MLATE V3

Open-source cross-tissue AI framework for data-driven optimization of 3D-printed
and bioprinted tissue-engineering scaffolds.

This repository contains the dataset, the full analysis pipeline and the web
application. Fitted models are **not** stored here; they are published to
Hugging Face and rebuilt from this code by `06_webapp/export_deployment.py`.

- Application: <https://huggingface.co/spaces/Saeed/MLATE>

## Dataset

| | |
|---|---|
| Samples | 2,646 |
| Source studies | 220 unique DOIs |
| Biomaterials | 130, in 13 functional classes |
| Cell lines | 186, plus an acellular category (187 distinct values) |
| Tissue categories | 18 |
| Printing parameters | 7 |
| Targets | Printability (0–3), Cell Response (1–5) |

`01_data/processed/MLATE_V3_dataset.xlsx` is the published dataset. Column order
is `Reference | DOI | tissue metadata | 130 biomaterials | Cell Line | Cell
Density | 7 printing parameters | Printability | Cell Response | duplicate
audit`.

Two DOIs appear both percent-encoded and plain, so a naive count of distinct
strings returns 222 for 220 studies. Scripts that count studies decode first.

Missing predictors are left as `NaN` on purpose: the file records what the source
studies actually reported, and all imputation happens in `02_preprocessing/`,
inside each cross-validation fold.

The dataset is provided in both `.xlsx` and `.csv` form; the two are identical.
Alongside it:

| file | contents |
|---|---|
| `reference/biomaterial_taxonomy.csv` | the 130 materials and their functional classes |
| `reference/cellline_synonyms.csv` | cell-line name normalization |

`01_data/build_dataset.py` additionally writes a column dictionary, an audit
workbook and an internal copy carrying provenance columns; these are
regenerated locally and not tracked here.

## Layout

```
mlate/                    shared library; nothing else hard-codes a path
  config.py               all paths and constants
  dataset.py              loader and the column contract
  style.py                figure design system, the only place colors live
  splits.py               random / DOI-grouped / leave-one-tissue-out
  imputation.py           tiered, missingness-aware imputers
  pipeline.py             fold-safe ColumnTransformer
  models.py               the classifier zoo
  deep.py                 tabular deep-learning architectures
  serving.py              uniform loading of every deployable model
  optimize.py             Bayesian scaffold optimization
  wssq.py                 the WSSQ objective
  protocol.py             LLM-assisted protocol generation
  prompts/                versioned prompt files

01_data/                  dataset construction and descriptive figures
02_preprocessing/         folds, imputation, leakage report
03_clustering/            unsupervised analysis and cluster selection
04_machine_learning/      conventional ML benchmark
05_deep_learning/         tabular DL and foundation models
06_webapp/                Streamlit application and deployment
07_wssq/                  WSSQ sensitivity analysis
08_interrater/            inter-rater agreement
verify.py                 checks every published figure and table
verify_comparability.py   proves all model classes share the same partitions
```

Results are written to `results/<stage>/` and are not tracked; every table and
figure in the paper is regenerated by the scripts above.

## Reproducing

Run from the repository root, in order:

```bash
python 01_data/build_dataset.py            # rebuild the published dataset
python 01_data/explore.py                  # descriptive figures and tables
python 01_data/figure_dataset_growth.py    # Figure 1
python 02_preprocessing/run.py             # freeze folds, leakage report
python 02_preprocessing/validate_imputation.py
python 03_clustering/select_k.py           # cluster-count selection
python 03_clustering/run.py
python 04_machine_learning/run.py          # conventional ML benchmark
python 05_deep_learning/figures.py         # deep and foundation models
python verify.py                           # non-zero exit on failure
```

The web application runs against exported artifacts:

```bash
python 06_webapp/export_deployment.py      # fit and export every model
python 06_webapp/build_app_data.py         # vocabularies, tables, corpus subset
streamlit run 06_webapp/app.py
```

## Validation protocols

Three protocols run side by side because they answer different questions.

| Protocol | Question | Test rows sharing a study with training |
|---|---|---|
| `random` | Interpolation: a formulation from a study already partly seen. This is the regime the web application operates in. | 99.4% |
| `doi` | Generalization to an unseen laboratory; 45 studies held out entirely. | 0% |
| `tissue` | Leave-one-tissue-out, supporting the cross-tissue claim. Studies spanning the held-out tissue are also removed from training. | 0% |

Hold-out sizes are 2,116 train / 530 test for `random` and 2,072 / 574 for
`doi`. The test partition is isolated before any model is fitted and is never
used for tuning; hyperparameters are selected by 10-fold cross-validation inside
the training partition only.

The gap between `random` and `doi` is a reported result, not an inconvenience.
Study membership carries real signal in a literature-mined dataset: 44% of
printability variance and 49% of cell-response variance sit between studies, and
68% of rows carry a material-plus-cell-line signature unique to one paper, so a
model can recognize the study and inherit its rating offset rather than learning
material–outcome relationships. The consequence differs sharply by target: the
best printability model falls from 0.792 to 0.606 weighted F1 under `doi`, while
cell response falls only from 0.773 to 0.769.

## Requirements

Python 3.11 or later. `pip install -r requirements.txt` for the analysis
environment; `06_webapp/requirements.txt` is a smaller serving-only environment
used by the Hugging Face Space.

An OpenRouter API key is needed only for protocol generation, and is read from
the environment or a git-ignored `.env` file. Nothing else requires a key.
